# 路线图

DSH Desktop Pro 企业版到 0.7.0 正式版、再到 0.8 的计划。按顺序推进；每一步的完成标准都写成可以检查的事实。日期是估计，试点反馈会改变后半段。

最后更新：2026-11-16

## 已经定下的

| 决定 | 内容 | 记录 |
|---|---|---|
| 一个安装包 | 有企业配置文件就是企业模式，否则是个人版 | ADR-0001 |
| 正式版前冻结功能 | 只做加固、修正和试点反馈 | — |
| 数据库 | 正式部署只支持 PostgreSQL；SQLite 只用于试用和演示 | ADR-0005 |
| 网关 Key | 每台设备一个，吊销设备即失效 | ADR-0003 |
| 「已生效」 | 按设备该拿到的配置计算，不按全组织版本号 | ADR-0002 |
| 可持续方式 | 付费支持；代码全部开源 | ADR-0006、ADR-0007 |
| 国内 IdP | 飞书、钉钉、企业微信放到正式版之后 | — |

## 0.7.0-beta.2 — 已发布（2026-11-16）

企业管理功能第一次走完整发布流程：四个平台安装包、PR 上三平台 CI。

## 0.7.0-beta.3 — 地基（进行中）

一次性把以后很难改的东西改对，不留过渡态。

- [x] 网关 Key 按设备签发；吊销设备即失效
- [x] 「已生效」与长轮询唤醒按设备指纹计算；下发、应用的审计只在变化时记录
- [x] OIDC 只用已验证的邮箱认人（`OIDC_TRUST_EMAIL` 显式放开）
- [x] 初始管理员令牌换成短会话，管理员用 SSO 登录后永久失效
- [x] 授权码、刷新令牌在并发下只能用一次；刷新令牌重放即结束会话；客户端刷新单飞
- [x] 设备证明覆盖请求体、只能用一次（协议版本 2）
- [x] 控制台拒绝跨站写请求
- [x] 网关：记不了账即停止转发、每人并发上限、背压
- [x] 保留期：逐请求记录、登录残留、可选的审计清理（带检查点）
- [x] CI 在 PostgreSQL 上跑服务端检查
- [x] ADR 与部署指南同步修订

完成标准：上面每一项都有自动检查；PostgreSQL 任务在 CI 上通过。

## 0.7.0-rc.1 — 试点与运维（约 3 周）

- [ ] 找到一个 10–50 人的试点组织，先文件模式、再服务端模式
- [ ] 亲自走一遍还没在界面上验证过的流程：真实 OIDC、文件模式、个人模式切换、托盘菜单、CSV 导入、Skill 编辑器、场景包分配与回滚、吊销设备、停用成员、额度拦截、macOS 与 Linux 客户端
- [ ] 运维文档：备份与恢复、跨版本升级、`DSH_SERVER_SECRET` 与组织签名密钥的轮换
- [ ] 跨版本升级的自动检查（旧库迁移到新版本后服务端检查仍通过）
- [ ] 修复个人版的 Windows `run_code` 问题（bruc3van/dsh-desktop-pro#31）

完成标准：试点组织在服务端模式下连续使用两周，没有阻塞问题。

## 0.7.0 正式版

门槛：rc.1 的完成标准达成；没有未处理的安全问题；PostgreSQL 检查持续通过。

## 0.8（正式版之后）

- 飞书、钉钉、企业微信登录与组织同步
- 长轮询改为事件通知（目前每台在线设备每 2 秒一次查询，上千台设备时需要改）
- 付费支持落地：范围、渠道、响应时限（ADR-0007）
- 视试点反馈决定：灰度发布、离线安装包、多币种计价

## 不做的

- 闭源模块、License 校验、按人数收费的功能（ADR-0006）
- 托管服务（ADR-0007）
- 在 0.7.0 正式版之前加新的管理功能
