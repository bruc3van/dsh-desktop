# ADR-0003 组织签名、密钥固定与设备证明

状态：已采纳

## 决定

- **下发物签名**：期望状态用组织的 Ed25519 密钥签名，签名覆盖规范化 JSON（键名排序、没有多余空白）。客户端只接受能用**已固定公钥**验证通过的文档。服务端模式的公钥在 `enrollment.json` 里；文件模式在旁边放 `organization-keys.json` 时，`managed.json` 必须签名。
- **密钥 ID 由公钥派生**（`ed25519:` + SPKI 的 SHA-256 前缀），不可能和别的公钥对不上号。轮换时先把新公钥加进注册文件，再改用新密钥签名，最后撤下旧公钥。
- **设备证明**：首次登录时设备生成自己的 Ed25519 密钥对，私钥用系统钥匙串加密保存（Electron safeStorage；Linux 没有钥匙串时退回为仅当前用户可读的文件）。之后每个 API 请求都带上对「方法 + 路径 + 时间戳」的签名，服务端用登记的公钥校验，允许 5 分钟时钟偏差。从这台电脑拷走的令牌，换一台机器就用不了。
- **登录**：系统浏览器 + OAuth 授权码 + PKCE，回调到本机回环地址（RFC 8252）。服务端只接受 `http://127.0.0.1:<端口>/callback`。令牌只以哈希形式入库；刷新令牌每次使用都会轮换。

## 放弃的方案

- **在应用内嵌浏览器登录**：拿不到公司 SSO 的已登录状态，也会让员工习惯在非浏览器窗口里输入公司密码。
- **JWT 访问令牌**：没法立即吊销，离职场景要求「停用后立刻失效」。

## 修订（0.7.0-beta.3）

- **网关 Key 归设备，不归人**：每台设备第一次拉取配置时签发自己的 Key。吊销设备立即吊销它的 Key，这个人的其他设备不受影响；停用成员吊销他所有设备的 Key。原先 Key 按人签发，吊销一台设备并不能让那台电脑上的 Key 失效，与「从这台电脑拷走的东西换台机器就用不了」的承诺不符。
- **设备证明覆盖请求体**：签名内容是「方法 + 路径 + 时间戳 + 请求体的 SHA-256」，并且每个证明只能用一次（服务端在有效期内记住用过的证明）。协议版本升为 2。多实例部署时，「只能用一次」只在同一实例内成立；请求体绑定在任何部署下都成立。
- **刷新令牌重放即吊销**：每次刷新都轮换，服务端记住上一枚；已被换掉的令牌再次出现，说明有人留了副本，整个会话结束，两边都要重新登录。领取授权码和轮换刷新令牌都用条件写入完成，并发的重复请求只有一个能成功。客户端的刷新改为同一时间只有一个。
- **邮箱必须经过验证才能认人**：OIDC 登录时，只有 ID Token 里 `email_verified` 为真，才用邮箱去匹配成员；否则只认 IdP 的 `sub`。不发送 `email_verified` 且只允许管理员设置邮箱的 IdP，可以用 `OIDC_TRUST_EMAIL=1` 明确选择信任。
- **初始管理员令牌只用于开局**：令牌换来一个 8 小时的会话（库里只存哈希，Cookie 里不再是令牌本身）；第一位管理员通过 IdP 登录控制台后，令牌永久失效。
- **控制台写操作校验来源**：带 `Origin` 或 `Sec-Fetch-Site` 且不来自控制台自己的写请求一律拒绝，不只依赖 Cookie 的 SameSite。
