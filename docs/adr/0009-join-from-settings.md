# ADR-0009 员工从客户端设置加入组织

状态：已采纳（0.7.0-beta.4）

## 背景

ADR-0001 只认 IT 放在系统目录里的 `enrollment.json` / `managed.json`。这适合有 MDM 或软件分发的公司，但很多团队没有：员工自己从官网下载安装包，装好后是个人版，界面里找不到任何进入企业模式的入口，只能等 IT 上门放文件。

## 决定

个人模式的桌面设置里加「组织」页：员工粘贴控制台「注册与分发」里的**加入地址**，形如 `https://dsh.example.com/#key=7F3A-92C1-…`。`#key=` 后面是组织签名公钥的**校验码**（公钥按 keyId 排序后的 SHA-256 前 128 位，8 组 4 位十六进制）。浏览器和客户端都不会把 `#` 后面的部分发给服务端；校验码由 IT 通过企业微信、邮件等其他渠道带到员工手里。客户端按下面的顺序加入。

1. **先问清楚是谁**。读取公开的 `/v1/discovery`，拿到组织名称和协议版本。弹出客户端自己的确认框，写明组织名称和服务端地址。员工不同意就到此为止，什么都不写。
2. **再走授权登录**。和 IT 登记的电脑一样，在系统浏览器里走 OAuth 2.0 + PKCE，回调到本机的一次性端口，然后为这台设备登记 Ed25519 设备密钥。
3. **登录成功后才拿公钥**。设备带着访问令牌和设备证明请求 `/v1/enrollment`，服务端返回服务端地址、组织和签名公钥。这个接口不对未登录的请求开放：组织的公钥，以及「这台电脑属于这个组织」，都是在员工本人登录之后才确定的。
4. **核对校验码**。加入地址带校验码时，取回的公钥必须和它一致，对不上就拒绝，并提示可能是地址抄错、组织换过公钥，或有人冒充服务端。
5. **最后才写入**。把登记信息写进客户端自己的目录 `<客户端目录>/enterprise/enrollment.json`（权限 0600），然后重启。重启后沿用刚才的登录，不用再登录一次。

中途任何一步失败或被取消，都会清掉这次的登录和设备身份，不留下加入了一半的状态。

规则：
- **IT 优先**：系统目录里有任何配置时，用户目录里的登记一律不看，也不能再加入别的组织。
- **员工可以离开**：自己加入的组织，「离开组织」会退出登录、移除组织下发的配置和登记，重启后回到个人使用。组织的对话记录保留在 `<客户端目录>/enterprise/dsh`。员工也可以先「改用个人模式」，以后再切回来。
- **用户目录里的登记读不出来时当作没有**，回到个人使用，不像系统目录那样拒绝启动：这个文件本来就归员工自己管，锁死只会把人挡在自己的电脑外面。
- **HTTPS 地址**可以不带校验码，证书由系统信任库验证；带了也会核对。
- **HTTP 地址必须带校验码**。企业内网往往没有 HTTPS 条件，但走 HTTP 时，同网段的人可以劫持流量、换掉组织公钥，之后签发的配置（包括必装插件，也就是代码）客户端都会认。校验码从服务端以外的渠道带来，换掉的公钥核对不过。本机地址（127.0.0.1、localhost）不要求校验码，方便试用。
- 走 HTTP 时仍有的风险：登录令牌和组织下发的网关 Key 在内网里明文传输。设备证明挡得住令牌被拿到别的机器上冒用，挡不住网关 Key 被抓包盗用。这和 IT 下发登记文件、服务端用 HTTP 时一样，文档和控制台都建议条件允许时改用 HTTPS（内网 CA 也可以）。
- 服务端返回的登记信息不带 `allowPersonal`。这一项是 IT 对自己管理的电脑做的决定；对自己加入的员工没有意义，他们随时可以离开。
- 控制台审计日志记一条「从客户端设置加入了组织」。

## 放弃的方案

- **公开下载登记信息，员工确认后直接写入**：谁知道地址谁就能让客户端认下一套签名公钥，「加入」这一步也没有经过员工的身份确认。改成登录后再发，公钥就跟员工本人的登录绑定在一起。
- **再加一个邀请码**：组织名称本来就由 `/v1/discovery` 公开；登录这一步已经限定了只有组织成员能加入。校验码是加入地址的一部分，不需要另外分发。
- **HTTP 一律拒绝**：很多内网做不到 HTTPS，员工就只能等 IT 用 MDM 下发文件，自己加入等于不可用。
- **HTTP 直接放开，只在确认框里警告**：员工没有能力判断网络有没有被劫持，警告只是把风险转给了他们。
- **信任自签证书（按校验码放行证书）**：要另外处理 TLS 校验，先引导 IT 把内网 CA 装进系统信任库。
- **把登记写进系统目录**：需要管理员权限。员工自己加入的组织本来就该由员工自己能撤销。
