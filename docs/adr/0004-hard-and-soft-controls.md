# ADR-0004 硬管控在网关，软管控在客户端

状态：已采纳

## 背景

员工对自己的电脑有完全控制权。客户端里的任何限制，有心的人都能绕过：改文件、换客户端、直接调用模型 API。

## 决定

- **硬管控放在模型网关**：真实的模型 Key 只存在网关里；每个员工拿到的是网关签发的个人虚拟 Key，可以限定模型、设预算、随时吊销。模型白名单、预算、内容审计都在网关执行。
- **软管控放在客户端**：工具禁用、锁定设置、下发插件和 Skill。目的是防止误操作、让正确的做法成为默认，不当作安全边界。
- 工具禁用用 `ctx.tools.guard` 实现（`enterprise/policy-plugin.ts`）：它在可扩展的 `tools/pre-execute` 之后运行，是单调的拒绝，后面的插件、预设或审批都不能把它改回允许。插件文件随客户端发布，通过 patch 层的 `insert` 按绝对路径挂载，不 fork 上游。

文档和界面里都如实说明这一点，不夸大客户端管控的能力。

## 已知限制

被禁用的工具仍然出现在模型的工具列表里，调用时被拒绝，模型会收到配置的原因。要从列表里去掉，需要上游提供按 profile 过滤工具的扩展点。
